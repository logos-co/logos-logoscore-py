    limit  axis=consumer   PARTLY CLOSED — three consumer points now, was one
           History, kept because the reasoning is the reusable part: the matrix had ONE
           consumer driver (`py`), so a cell proved a provider agreed with the python client,
           not that two consumer surfaces agreed with each other. That hid a real defect — the
           event bridge failing to decode tagged bytes into a QByteArray was invisible because
           the undecoded map round-trips and the py client decodes the tag itself; it took
           asserting the bridge directly (logos-protocol test_event_payload_fidelity.cpp) to
           see it. It also recorded, correctly, that adding the existing C++/Rust proxies would
           NOT close the hole: both are lp/Rust-client consumers, so they share the py blind
           spot for the Qt-typed path.
           Now measured, not argued. The axis runs py + qtproxy-sync + qtproxy-async. Two
           findings came straight out of it: M3 became measurable (and is now an ordinary
           xfail), and Q1 — the Qt dispatch coercing hostile arguments — was not previously
           known at all. The live cell counts are in the register rather than restated here,
           because a count written into prose goes stale silently and this block is reproduced
           verbatim in every report.
           What is STILL open on this axis: * QML. No driver replays cases.json through the
           LogosQmlBridge, and the two skip[] entries describe exactly that surface. * The
           cdylib/Rust proxy. Buildable and driveable by the same --proxy-consumer flag; not
           wired in. * The lp proxy. Measured here for ATTRIBUTION (it is what proves Q1 and M3
           are the Qt style rather than the extra hop) but not carried as a standing consumer:
           it has 2 divergent cases of its own that would need registry entries first. * The
           ext table (ext-cases.json) still has no proxy at all, so every one of its cells
           remains single-consumer. It does now run BOTH providers, so it has a provider
           differential; the consumer axis is the half still missing.
    limit  axis=transport  OPEN
           Every cell is measured over LocalSocket/QtRO: run_matrix.py builds the daemon with
           no `transports=`, and there is no flag to change it. The plain (tcp/tcp_ssl) wire is
           unreachable from this table. That mattered for uint: RpcValue's variant had no
           unsigned alternative (logos-protocol cpp/implementations/plain/rpc_value.h), so a
           uint64 above int64max wrapped to -1 there — a DIFFERENT wrong answer than the one M6
           described, which this matrix would not have matched. Fixed in the same
           logos-protocol PR as M6, but found only by reading the code: no cell here could
           reach it. The regression guard for it lives where it can run — logos-logoscore-py's
           integration table, which now carries 2^63, 2^64-1 and 2^53+1 and is replayed over
           local, tcp and tcp_ssl.
